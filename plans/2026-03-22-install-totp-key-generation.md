# Install TOTP Encryption Key Generation

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auto-generate `TOTP_ENCRYPTION_KEY` during installation so operators don't need to know it exists.

**Architecture:** The shared-hosting package uses `config.php` (not `.env`) to store secrets. `package/index.php` maps config keys → `$_ENV` vars that the backend reads via `Env::get()`. The installer (`package/install.php`) already generates the INSTALL key and writes `config.php`; it should also generate the TOTP encryption key in Step 2.

**Tech Stack:** PHP 8.3, `random_bytes()` / `bin2hex()` for key generation; no new dependencies.

---

## Context

### Two install paths

| Path | Config file | Key source |
|------|-------------|------------|
| Shared hosting (`package/`) | `config.php` written by `install.php` | **Must be generated by installer** |
| Docker / dev (`backend/`) | `.env` copied from `.env.example` | Operator runs `openssl rand -hex 32` manually |

This plan covers the **shared-hosting path only**. The Docker path already documents manual generation in `.env.example` and no automation is needed there.

### How the package runtime reads config

`package/index.php` maps `config.php` entries to `$_ENV`:
```php
$_ENV['DB_HOST'] = $config['db']['host'];
// ... etc
```
`TotpService` then calls `Env::get('TOTP_ENCRYPTION_KEY')`.

The key is currently missing from both `config.sample.php` and the `index.php` mapping, so any TOTP operation on a package install would throw `Missing env var: TOTP_ENCRYPTION_KEY`.

### Files

| File | Change |
|------|--------|
| `package/config.sample.php` | Add `security.totp_encryption_key` placeholder |
| `package/install.php` | Generate key in Step 2, write to `config.php` |
| `package/index.php` | Map `config['security']['totp_encryption_key']` → `$_ENV['TOTP_ENCRYPTION_KEY']` |

### Milestone 3 — package/install.php

Auto-generate the key during Step 2 (Database) and include it in the written `config.php`.

#### 3.1 Locate where `config.php` is written

In Step 2's `case '2':` POST handler, `$configContent` is built with `var_export([...])`. The `security` section must be added here.

- [ ] 3.1 Add key generation at the top of the `case '2':` block (before the DB connection test):
```php
// Generate a fresh TOTP encryption key for this installation
$totpKey = bin2hex(random_bytes(32));
```

- [ ] 3.2 Add `security` to the `var_export` array in `$configContent`:
```php
'security' => [
    'totp_encryption_key' => $totpKey,
],
```

The full `$configContent` assignment becomes:
```php
$configContent = "<?php\n\nreturn " . var_export([
    'db' => [...],
    'app' => [...],
    'session' => [...],
    'api_token' => [...],
    'security' => [
        'totp_encryption_key' => $totpKey,
    ],
], true) . ";\n";
```

- [ ] 3.3 Verify `install.php` parses cleanly:

## Out of Scope

- **Docker / `.env` path**: `.env.example` already documents `openssl rand -hex 32`. No automation needed.
- **Key rotation**: Not in scope; reset is done via `install.php?action=migrate` (update path).
- **Key display to operator**: The key is opaque — operators never need to see it. Unlike `INSTALL_KEY`, it's not manually copied.
