# E2E Testing Pattern 006: Page Object Fixtures

## Overview

**Pattern 006** eliminates boilerplate page object initialization by using Playwright fixtures to automatically inject ready-to-use page objects into tests. Instead of manually creating page objects in every `beforeEach` hook, fixtures provide a clean dependency injection mechanism that keeps tests focused on behavior, not setup.

**Benefits:**
- Eliminates repetitive page object instantiation (~10 lines per test file)
- Fixtures can handle common setup (login, navigation)
- Cleaner test code focused on behavior
- Easy to create composite fixtures (e.g., authenticated products page)
- Type-safe fixture injection with TypeScript

## Problem: The Anti-Pattern

### Before Pattern 006 (Anti-Pattern)

```typescript
import { test, expect } from '@playwright/test'
import { LoginPage, ProductsPage } from '../../pages'

test.describe('Admin Frontend - Products Page', () => {
  let loginPage: LoginPage
  let productsPage: ProductsPage

  // ❌ ANTI-PATTERN: Manual initialization in beforeEach
  test.beforeEach(async ({ page }) => {
    loginPage = new LoginPage(page)
    productsPage = new ProductsPage(page)

    await loginPage.navigate()
    await loginPage.login('admin@example.com', 'password123')
    await productsPage.navigate()
  })

  test('should create product', async () => {
    // Setup code clutters test intent
    await productsPage.openCreateModal()
    await productsPage.fillProductForm('Coffee', '3.50')
    await productsPage.submitProductForm()
  })
})
```

**Issues with this approach:**
- Repetitive boilerplate in every test file using page objects
- Setup code in `beforeEach` obscures test structure
- Must manually manage instance state
- Not scalable as more page objects are created
- Login setup duplicated across multiple test files

## Solution: Page Object Fixtures

### After Pattern 006 (Using Fixtures)

```typescript
import { test, expect } from '@playwright/test'

// ✅ CLEAN: Fixtures handle all setup
test.describe('Admin Frontend - Products Page', () => {
  test('should create product', async ({ loginPage, productsPage }) => {
    // No setup needed - fixtures provide ready-to-use page objects
    // And they're already authenticated and on the products page
    await productsPage.openCreateModal()
    await productsPage.fillProductForm('Coffee', '3.50')
    await productsPage.submitProductForm()
  })
})
```

**Advantages:**
- One-line fixture injection in test signature
- Setup handled by fixture, not test
- Test focuses on behavior, not initialization
- Fixtures reusable across all test files
- Easy to extend with custom setup logic

## Fixture Implementation

### Basic Fixture Structure

Create `tests/fixtures/pageObjects.ts`:

```typescript
import { test as baseTest, Page } from '@playwright/test'
import { LoginPage, ProductsPage } from '../../pages'

/**
 * Base fixture that provides a Playwright Page
 * (already provided by baseTest, included for clarity)
 */

/**
 * Fixture: loginPage
 * Provides LoginPage instance
 */
const loginPageFixture = async ({ page }: { page: Page }, use: (value: LoginPage) => Promise<void>) => {
  const loginPage = new LoginPage(page)
  await use(loginPage)
}

/**
 * Fixture: productsPage
 * Provides ProductsPage instance
 */
const productsPageFixture = async ({ page }: { page: Page }, use: (value: ProductsPage) => Promise<void>) => {
  const productsPage = new ProductsPage(page)
  await use(productsPage)
}

/**
 * Fixture: authenticatedProductsPage
 * Provides ProductsPage with admin already logged in and on products page
 * Depends on: loginPage, productsPage fixtures
 */
const authenticatedProductsPageFixture = async (
  { loginPage, productsPage }: { loginPage: LoginPage; productsPage: ProductsPage },
  use: (value: ProductsPage) => Promise<void>
) => {
  // Login and navigate to products page
  await loginPage.navigate()
  await loginPage.login('admin@example.com', 'password123')
  await productsPage.navigate()

  // Provide authenticated page object to test
  await use(productsPage)
}

/**
 * Extend base test with custom fixtures
 */
export const test = baseTest.extend({
  loginPage: loginPageFixture,
  productsPage: productsPageFixture,
  authenticatedProductsPage: authenticatedProductsPageFixture,
})

// Re-export expect for convenience
export { expect }

/**
 * TypeScript fixture types
 * Automatically generated by baseTest.extend()
 */
declare global {
  namespace PlaywrightTest {
    interface Fixtures {
      loginPage: LoginPage
      productsPage: ProductsPage
      authenticatedProductsPage: ProductsPage
    }
  }
}
```

### Fixture Usage in Tests

Once fixtures are defined, use them by updating your test imports:

```typescript
// ❌ BEFORE: Import baseTest
import { test, expect } from '@playwright/test'

// ✅ AFTER: Import from fixtures
import { test, expect } from '../fixtures/pageObjects'
import { LoginPage, ProductsPage } from '../../pages'

test.describe('Admin Frontend - Products Page', () => {
  // Test 1: Simple fixture usage
  test('should display products page', async ({ productsPage }) => {
    await productsPage.navigate()
    expect(await productsPage.isLoaded()).toBeTruthy()
  })

  // Test 2: Using authenticated fixture
  test('should create product', async ({ authenticatedProductsPage }) => {
    // No login setup needed - fixture handles it
    const page = authenticatedProductsPage
    await page.openCreateModal()
    await page.fillProductForm('Coffee', '3.50')
    await page.submitProductForm()
  })

  // Test 3: Using both fixtures
  test('logout and login again', async ({ loginPage, productsPage }) => {
    await loginPage.navigate()
    await loginPage.login('admin@example.com', 'password123')
    await productsPage.navigate()
    expect(await productsPage.isLoaded()).toBeTruthy()
  })

  // Test 4: Manual page object usage (when needed)
  test('direct page access', async ({ page }) => {
    // Still have access to base page for low-level interactions
    await page.goto('http://localhost:5173/login')
  })
})
```

## Advanced Patterns

### Fixture Scope

Fixtures can have different scopes:

```typescript
// Test scope (default): Fixture runs before each test
test.extend({
  productsPage: async ({ page }, use) => {
    const productsPage = new ProductsPage(page)
    console.log('Creating fixture') // Logs before each test
    await use(productsPage)
    console.log('Cleaning up fixture') // Logs after each test
  }
})

// Test scope with setup/teardown
test.extend({
  authenticatedProductsPage: async ({ loginPage, productsPage }, use) => {
    // Setup: Login before test
    await loginPage.navigate()
    await loginPage.login('admin@example.com', 'password123')
    await productsPage.navigate()

    // Test runs here
    await use(productsPage)

    // Teardown: Logout after test (optional)
    // await loginPage.logout()
  }
})
```

### Fixture Composition (Depending on Other Fixtures)

Fixtures can depend on other fixtures:

```typescript
const authenticatedProductsPageFixture = async (
  { loginPage, productsPage },  // Dependencies
  use
) => {
  // Uses both loginPage and productsPage
  await loginPage.navigate()
  await loginPage.login('admin@example.com', 'password123')
  await productsPage.navigate()
  await use(productsPage)
}

// Or with explicit typing:
const authenticatedProductsPageFixture = async (
  { loginPage, productsPage }: { loginPage: LoginPage; productsPage: ProductsPage },
  use: (value: ProductsPage) => Promise<void>
) => {
  // Full TypeScript support
  await use(productsPage)
}
```

### Multiple Fixture Variants

Create different fixture variants for different scenarios:

```typescript
export const test = baseTest.extend({
  // Basic fixtures
  loginPage: loginPageFixture,
  productsPage: productsPageFixture,

  // Authenticated variants
  authenticatedLoginPage: async ({ loginPage }, use) => {
    await loginPage.navigate()
    await loginPage.login('admin@example.com', 'password123')
    await use(loginPage)
  },

  authenticatedProductsPage: async ({ loginPage, productsPage }, use) => {
    await loginPage.navigate()
    await loginPage.login('admin@example.com', 'password123')
    await productsPage.navigate()
    await use(productsPage)
  },

  // Additional fixtures for specific scenarios
  emptyProductsPage: async ({ loginPage, productsPage }, use) => {
    await loginPage.navigate()
    // Login with user that has no products
    await loginPage.login('user-with-no-products@example.com', 'password123')
    await productsPage.navigate()
    await use(productsPage)
  },
})
```

## Migration Guide

### Step 1: Create Fixture File

Create `tests/fixtures/pageObjects.ts` with all fixture definitions:

```typescript
import { test as baseTest, Page } from '@playwright/test'
import { LoginPage, ProductsPage } from '../../pages'

const loginPageFixture = async ({ page }: { page: Page }, use) => {
  const loginPage = new LoginPage(page)
  await use(loginPage)
}

const productsPageFixture = async ({ page }: { page: Page }, use) => {
  const productsPage = new ProductsPage(page)
  await use(productsPage)
}

const authenticatedProductsPageFixture = async (
  { loginPage, productsPage }: { loginPage: LoginPage; productsPage: ProductsPage },
  use
) => {
  await loginPage.navigate()
  await loginPage.login('admin@example.com', 'password123')
  await productsPage.navigate()
  await use(productsPage)
}

export const test = baseTest.extend({
  loginPage: loginPageFixture,
  productsPage: productsPageFixture,
  authenticatedProductsPage: authenticatedProductsPageFixture,
})

export { expect } from '@playwright/test'
```

### Step 2: Update Test Imports

Before:
```typescript
import { test, expect } from '@playwright/test'
import { LoginPage, ProductsPage } from '../../pages'
```

After:
```typescript
import { test, expect } from '../fixtures/pageObjects'
```

### Step 3: Remove Manual Initialization

Before:
```typescript
test.describe('Products', () => {
  let loginPage: LoginPage
  let productsPage: ProductsPage

  test.beforeEach(async ({ page }) => {
    loginPage = new LoginPage(page)
    productsPage = new ProductsPage(page)
    await loginPage.navigate()
    await loginPage.login('admin@example.com', 'password123')
    await productsPage.navigate()
  })

  test('should create product', async () => {
    // ...
  })
})
```

After:
```typescript
test.describe('Products', () => {
  test('should create product', async ({ authenticatedProductsPage }) => {
    // ...
  })
})
```

### Step 4: Update Test Signatures

Add fixture parameters to test signatures:

```typescript
// Simple fixture usage
test('should display page', async ({ productsPage }) => {
  // Use productsPage
})

// Multiple fixtures
test('should login and navigate', async ({ loginPage, productsPage }) => {
  // Use both
})

// Authenticated fixture (includes login and navigation)
test('should create product', async ({ authenticatedProductsPage }) => {
  // Already logged in and on products page
})
```

## Benefits Comparison

| Aspect | Without Fixtures | With Fixtures |
|--------|------------------|---------------|
| **Setup Code per Test File** | ~10 lines in beforeEach | 0 lines (handled by fixture) |
| **Test Readability** | Cluttered with setup | Clean and focused |
| **Reusability** | Setup duplicated | Centralized in fixture |
| **Type Safety** | Manual instantiation | Automatic TypeScript types |
| **Maintenance** | Update setup in each file | Update once in fixture |
| **Test Isolation** | Manual handling | Fixtures manage scope |
| **Composability** | Must chain manually | Fixtures compose easily |

## Best Practices

### ✅ DO

1. **Create fixtures for reusable setup**
   ```typescript
   // Good: Fixture handles common setup
   authenticatedProductsPage: async ({ loginPage, productsPage }, use) => {
     await loginPage.navigate()
     await loginPage.login('admin@example.com', 'password123')
     await productsPage.navigate()
     await use(productsPage)
   }
   ```

2. **Use fixture names that describe the state**
   ```typescript
   // Good names
   loginPage              // Basic page object
   authenticatedProductsPage  // Authenticated state implied
   emptyProductsPage      // State clearly described
   ```

3. **Leverage fixture composition**
   ```typescript
   // Good: Build complex fixtures from simple ones
   authenticatedProductsPage: async ({ loginPage, productsPage }, use) => {
     // Uses both fixtures
   }
   ```

4. **Keep fixtures focused**
   ```typescript
   // Good: One responsibility per fixture
   loginPage: create LoginPage instance
   authenticatedProductsPage: login + navigate to products
   ```

### ❌ DON'T

1. **Don't create fixtures that do too much**
   ```typescript
   // Bad: Too many responsibilities
   allSetUp: async ({ loginPage, productsPage, membersPage }, use) => {
     // Sets up everything
   }
   ```

2. **Don't skip the fixture if it's simple**
   ```typescript
   // Still good: Even simple fixtures worth creating
   productsPage: async ({ page }, use) => {
     const productsPage = new ProductsPage(page)
     await use(productsPage)
   }
   ```

3. **Don't mix fixtures with global setup**
   ```typescript
   // Fixtures for test-specific setup, not global state
   // Use playwright.config.ts globalSetup for database migrations, etc.
   ```

4. **Don't hardcode credentials in fixtures**
   ```typescript
   // Bad: Credentials should be in environment
   await loginPage.login('admin@example.com', 'password123')

   // Better: Use environment variables
   const email = process.env.ADMIN_EMAIL || 'admin@example.com'
   const password = process.env.ADMIN_PASSWORD || 'password123'
   await loginPage.login(email, password)
   ```

## Verification Checklist

Before using fixtures in your tests, verify:

- [ ] Fixture file created at `tests/fixtures/pageObjects.ts`
- [ ] All page objects imported and instantiated in fixtures
- [ ] Test imports updated to use custom test (from fixtures)
- [ ] Test signatures updated with fixture parameters
- [ ] Manual `beforeEach` initialization removed
- [ ] All tests still pass
- [ ] TypeScript shows no type errors
- [ ] Fixtures have clear, descriptive names
- [ ] Fixture dependencies are explicit
- [ ] No duplicate setup code across fixtures

## Example: Complete Test Suite with Fixtures

```typescript
import { test, expect } from '../fixtures/pageObjects'

test.describe('Admin Frontend - Products Page', () => {
  test('should display products page', async ({ productsPage }) => {
    await productsPage.navigate()
    expect(await productsPage.isLoaded()).toBeTruthy()
    expect(await productsPage.isTableVisible()).toBeTruthy()
  })

  test('should open create product modal', async ({ authenticatedProductsPage }) => {
    // No login needed - fixture handled it
    await authenticatedProductsPage.openCreateModal()
    expect(await authenticatedProductsPage.isCreateModalOpen()).toBeTruthy()
  })

  test('should create product', async ({ authenticatedProductsPage }) => {
    const productName = `Test Product ${Date.now()}`
    const productPrice = '5.99'

    await authenticatedProductsPage.openCreateModal()
    await authenticatedProductsPage.fillProductForm(productName, productPrice)
    await authenticatedProductsPage.submitProductForm()

    // Wait for submission
    await authenticatedProductsPage.waitForDebounce(1000)
  })

  test('should search products', async ({ authenticatedProductsPage }) => {
    const searchTerm = 'coffee'
    await authenticatedProductsPage.search(searchTerm)

    const searchValue = await authenticatedProductsPage.getSearchValue()
    expect(searchValue).toBe(searchTerm)
  })
})
```
